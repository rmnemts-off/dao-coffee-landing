# DAO COFFEE GROUP

Русскоязычный лендинг: оборудование разных брендов, автоматизация кофе-точек, кофе ДАО и СТМ, комплектация общепита. Текущая версия — статический фронтенд. Отправка заявок на сервер ещё не подключена.

## Запуск

Node.js 22 или новее. Внешних npm-зависимостей нет, установка пакетов не требуется.

```sh
git clone https://github.com/rmnemts-off/dao-coffee-landing.git
cd dao-coffee-landing
npm run dev
```

Открыть http://localhost:4321/. Если порт занят, задать переменную `PORT` при запуске. Сервер привязан к `127.0.0.1`, отдаёт только `site/` и не реализует API заявок.

```sh
npm run check
```

Команда проверяет синтаксис JavaScript; адаптивность и поведение форм проверяются отдельно в браузере.

## Файлы

- `site/index.html` — редактируемая исходная страница, без шага генерации.
- `site/privacy.html`, `site/consent.html` — политика обработки персональных данных и отдельное согласие, доступные из форм; аналитика сейчас не подключается.
- `site/styles/design.css` — единственный подключённый CSS: палитра, локальные шрифты, композиция, адаптивность, формы.
- `site/scripts/main.js` — меню, шапка, смена общего фона и анимации.
- `site/scripts/forms.js` — модальное окно, контекст заявки, черновики в памяти, маска телефона и локальная валидация. Сетевой отправки сейчас нет.
- `site/assets/` — используемые изображения, логотип, локальная GSAP и WOFF2. Лицензии шрифтов находятся в `site/assets/fonts/licenses/`; заголовок лицензии GSAP сохранён в vendor-файле.
- `scripts/serve.mjs` — локальный статический просмотр.
- `AGENTS.md`, `CLAUDE.md`, `docs/` — инструкции для совместной разработки.

Статический корень для размещения — `site/`. Указание этой папки не публикует сайт. Текущий сервер просмотра не заменяет production-бэкенд. Выбор и настройка размещения API — задача бэкенд-разработчика с учётом подтверждённого хостинга.

## Два разработчика

Оба работают в отдельных клонах/worktree, начиная от общей версии `main`:

| Ветка | Ответственность | Стартовое задание |
| --- | --- | --- |
| `frontend/design` | Визуал, адаптивность, анимации | [FRONTEND_START.md](docs/FRONTEND_START.md) |
| `backend/telegram` | API, отправка в Telegram, состояния формы | [BACKEND_START.md](docs/BACKEND_START.md) |

Изменения передаются отдельными PR в `main`. Слияние и публикация выполняются после проверки и команды Романа. Это рабочая договорённость; защита веток настройками GitHub пока не включалась.

Общий интерфейс описан в [FORM_CONTRACT.md](docs/FORM_CONTRACT.md). Фронтенд сохраняет имена полей/контексты; бэкенд владеет `forms.js` и подключением транспорта. Изменения общих файлов явно отмечаются в PR. После принятия одного PR второй разработчик обновляет свою ветку из `main`, проверяет совместную работу и только затем завершает PR.

Для переключения на уже созданную ветку после клонирования:

```sh
git switch --track origin/frontend/design
```

Для бэкенда аналогично: `git switch --track origin/backend/telegram`. Если локальная ветка уже существует, использовать `git switch` с её именем.

## Границы передачи

В репозитории только актуальный сайт, необходимые файлы запуска и инструкции разработки. Переписка, исследования, договоры, исходные архивы, скриншоты обсуждений, прежние варианты сайта и секреты не публикуются. Добавление нового корневого каталога требует явного обновления `.gitignore`; внутри `site/`, `scripts/`, `docs/`, `backend/` и `netlify/` новые рабочие файлы разрешены.

Форма сейчас показывает честное сообщение об отсутствии отправки. Проверенные публичные контакты — самостоятельные ссылки; они не означают, что выбран получатель Telegram-бота. Реальные токены, chat ID и согласованный тестовый адресат передаются разработчику отдельно. Перед production-приёмом заявок необходимо подтвердить получателя и тексты документов для обработки персональных данных.
