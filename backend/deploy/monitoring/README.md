# DAO: частный мониторинг одного VPS

Подготовлены конфигурации для установки и проверки на согласованном VPS. Аудит нового сервера 25.10.2026 подтвердил Ubuntu 24.04.1 amd64, cgroup v2 и 961 МиБ RAM (тариф с 1 ГБ); исходно swap отсутствовал. Этот документ сам по себе не подтверждает успешный запуск сервисов. Все команды ниже выполняются оператором **на согласованном VPS**, кроме явно отмеченного SSH-туннеля. Эти файлы не меняют nginx, API, домен или DNS.

Состав: Grafana OSS → локальный Prometheus → node_exporter. Native systemd, без Docker, Loki, Alertmanager, агентов логов и внешней отправки метрик. Собираются CPU, RAM, локальные диски, сеть, load average и uptime ОС. Заявки, телефоны, токены и журналы запросов в Prometheus не поступают. Дашборд не проверяет сайт, процесс Node.js или доставку Bitrix24.

## Доступ и ресурсы

| Сервис | Привязка | MemoryHigh / MemoryMax |
| --- | --- | --- |
| Grafana | `127.0.0.1:3000` | 256 / 512 МиБ |
| Prometheus | `127.0.0.1:9090` | 96 / 192 МиБ |
| node_exporter | `127.0.0.1:9100` | 24 / 48 МиБ |

Порты не открывать в firewall VPS/провайдера и не публиковать через nginx. Доступ к Grafana — через SSH-туннель и отдельный пароль `dao-admin`. Анонимный доступ, регистрация, SMTP, внешние snapshots, аналитика и встроенный alerting выключены. Нет правил, отправляющих сообщения.

Сумма верхних лимитов памяти мониторинга — 752 МиБ. Это защитные ограничения, **не измеренное потребление, не резерв памяти и не гарантия достаточности VPS с 1 ГБ RAM**. Вместе с ОС, Nginx и другими службами потребление может превысить доступные 961 МиБ. При превышении `MemoryHigh` ядро ограничивает выполнение процессов и пытается освободить память; при достижении `MemoryMax` и невозможности освободить память сервис может быть остановлен OOM killer. `CPUWeight=25` даёт мониторингу меньший относительный приоритет; это не жёсткая квота CPU. Если сервис не укладывается в лимит, исследовать причину и ресурсы VPS, а не снимать ограничения автоматически. [Требования Grafana](https://grafana.com/docs/grafana/latest/setup-grafana/installation/) называют 512 МБ нижней границей для оценки; рекомендуемый небольшой production-профиль выше этого VPS.

Перед первым запуском на данном сервере подготовить **2 ГиБ swap** и проверить его активность через `swapon --show`. Swap страхует от кратковременного дефицита RAM при установке и запуске; он не заменяет оперативную память, а постоянный обмен с диском может замедлить весь сервер. Сначала проверить файловую систему, свободный диск и отсутствие существующего swap-файла; новую запись в `/etc/fstab` добавлять без дублирования и с резервной копией исходного файла. Настройка swap выполняется отдельно от этого установщика.

На первом этапе **API остаётся выключенным** до настройки Bitrix24. Перед его включением отдельно измерить полную связку: существующий unit API допускает ещё 512 МиБ, поэтому суммарный верхний предел уже превышает физическую RAM даже без ОС. Нужны проверка под рабочей нагрузкой и решение о лимитах либо увеличении памяти VPS. Проверять `MemoryCurrent`, `MemoryPeak`, `NRestarts`, свободную память, swap-in/swap-out и сообщения OOM; одного успешного старта недостаточно для заявления об устойчивой работе.

Сбор раз в 30 секунд, обновление дашборда раз в минуту, небольшой явный набор collectors и метрик. Prometheus хранит до 3 дней или 1 ГБ блоков — срабатывает первое ограничение. Это **не жёсткая квота всего каталога**: WAL, текущие данные и compaction требуют дополнительного места. Перед установкой оставить не менее 3 ГБ свободного пространства под мониторинг и запас для ОС/релизов. [Ограничения хранения Prometheus](https://prometheus.io/docs/prometheus/latest/storage/)

Операционные сообщения сервисов идут в journal на уровне warning с ограничением частоты. Общая ротация journal принадлежит настройке ОС; этот комплект не меняет её и не собирает журнал API.

## Установка

1. Проверить `cat /etc/os-release`, `uname -m`, `free -h`, `df -h /var/lib`, `systemctl --version`. Установщик допускает только **Debian 12/13 или Ubuntu 22.04/24.04**, `amd64`/`arm64`, systemd и cgroup v2. Для другой ОС сначала адаптировать и проверить пакетные пути. Ubuntu должен иметь официальный компонент с пакетами Prometheus; если `apt-cache policy` не показывает кандидата, проверить источники Ubuntu, не добавлять случайный PPA.
2. Перенести эту папку из принятого SHA без `.env` и закрытых файлов. Установщик предназначен только для первой установки: наличие Grafana/Prometheus, старых каталогов или занятых портов останавливает его. Прежнюю установку мигрировать отдельно.
3. На VPS перейти в папку `backend/deploy/monitoring` и подготовить подписанный репозиторий:

   ```sh
   sudo bash install.sh --prepare
   ```

   Этап устанавливает штатные `ca-certificates`, `curl`, `gnupg`, `openssl`, `python3`, добавляет **Grafana stable OSS** из официального APT и показывает `apt-cache policy`. Prometheus и exporter берутся из подписанных репозиториев ОС. Проверить версии **и источники**: Grafana — `apt.grafana.com`, Prometheus/exporter — официальные Debian/Ubuntu. Не использовать сторонние замены пакетов. Ключ Grafana проверяется по опубликованному fingerprint `B53AE77BADB630A683046005963FA27710458545`; при ротации установка останавливается для проверки. [Официальный APT Grafana](https://apt.grafana.com/), [инструкция установки](https://grafana.com/docs/grafana/latest/setup-grafana/installation/debian/)
4. Передать три точные версии из вывода предыдущего шага. Слова `VERSION` ниже — placeholders, установщик их отклонит:

   ```sh
   sudo bash install.sh --install GRAFANA_VERSION PROMETHEUS_VERSION NODE_EXPORTER_VERSION
   ```

   Пароль вводится дважды скрытым вводом из терминала: уникальный, не менее 16 символов, без пробелов в начале/конце. Сохранить его в менеджере паролей. Не передавать пароль аргументом команды или переменной окружения; не запускать установщик с `bash -x`.

   До установки пакетов сервисы **постоянно маскируются** в systemd. Они запускаются только после записи loopback-конфигурации, секретов и ограничений. Если этап завершился ошибкой, маски сохраняются и действуют после перезагрузки; не снимать их до проверки. Автоматического повторного запуска установщика поверх частичной установки нет: завершить настройку по проверенному diff или выполнить удаление ниже.

   Выбранные версии сохраняются в `/var/lib/dao-monitoring-install/versions.txt`; три пакета ставятся на `apt-mark hold`, чтобы обновлять их вручную. Установка не выполняет `apt upgrade` ОС. Версии намеренно не выдуманы до определения ОС: фиксируется точный пакет, доступный в её подписанном репозитории.

## Файлы на сервере

| Источник | Назначение |
| --- | --- |
| `prometheus.yml` | `/etc/prometheus/dao-prometheus.yml` |
| `grafana/grafana.ini` | `/etc/grafana/grafana.ini` |
| `grafana/provisioning/datasources/dao-prometheus.yml` | `/etc/grafana/provisioning/datasources/dao-prometheus.yml` |
| `grafana/provisioning/dashboards/dao-host.yml` | `/etc/grafana/provisioning/dashboards/dao-host.yml` |
| `grafana/dashboards/dao-host.json` | `/var/lib/grafana/dashboards/dao-host.json` |
| `systemd/*.conf` | `/etc/systemd/system/<имя-сервиса>.service.d/dao-monitoring.conf` |

`/etc/grafana/dao-secrets/` — каталог `root:grafana`, `0750`; `admin-password` и `secret-key` — `0640`. Пользовательские процессы их читать не должны. Grafana получает значения через официальный `$__file{...}` provider. Пароль администратора используется **только при создании новой БД**: последующая правка файла не меняет пароль учётной записи. Менять пароль через интерфейс Grafana и обновлять защищённую запись владельца. `secret-key` сохранять при переносе/восстановлении. [Конфигурация Grafana](https://grafana.com/docs/grafana/latest/setup-grafana/configure-grafana/)

Данные Prometheus: `/var/lib/prometheus/dao-metrics`. Grafana использует собственную встроенную SQLite `/var/lib/grafana/grafana.db` для пользователей и настроек, без дополнительного сервера БД. Это небольшой одиночный экземпляр мониторинга; он не добавляет хранилище заявок в API. Дашборд и datasource восстанавливаются из файлов, редактирование provisioned-версии через UI выключено. [Provisioning Grafana](https://grafana.com/docs/grafana/latest/administration/provisioning/)

## Проверка и вход

После первого сбора метрик (обычно до 30–60 секунд) на VPS:

```sh
sudo bash validate.sh
sudo systemctl show grafana-server prometheus prometheus-node-exporter -p Id -p MemoryCurrent -p MemoryPeak -p NRestarts -p Result
```

`validate.sh` проверяет активность сервисов, **только** IPv4 loopback на трёх портах, готовность БД Grafana и Prometheus, `up{job="node"}=1`, отказ анонимному API-запросу. Он не отправляет заявки или сообщения и не выводит секреты. Если Prometheus ещё не собрал метрики, повторить после первого scrape. На старых systemd поле `MemoryPeak` может отсутствовать; ориентироваться на доступные показатели и журнал.

На своём компьютере, подставив согласованные SSH пользователя и адрес:

```sh
ssh -N -o ExitOnForwardFailure=yes -L 127.0.0.1:3000:127.0.0.1:3000 USER@VPS
```

Открыть **http://localhost:3000/**, войти как `dao-admin` со своим паролем. Дашборд «DAO · Сервер» — домашняя страница и папка DAO. Пароль и токены не вставлять в URL. При завершении туннеля `Ctrl+C` доступ прекращается. Если локальный порт 3000 занят, сначала освободить его; конфигурация `root_url` рассчитана на этот адрес.

Проверить визуально все панели после накопления 5 минут: CPU, RAM, диск `/`, диски, 1/5/15-minute load, число vCPU, оба направления сети и uptime. Убедиться, что «Нет данных» не трактуется как ноль. С внешнего компьютера проверить, что `VPS:3000`, `VPS:9090`, `VPS:9100` недоступны, а SSH-туннель работает. После согласованного перезапуска VPS повторить `validate.sh` и проверить отсутствие неожиданного роста памяти/перезапусков. Сайт и заявки проверяются отдельно, без тестового спама.

## Обновление и откат

- Конфигурация/дашборд: изменения через PR и принятый `main`; сохранить предыдущую версию файлов, перенести соответствующие файлы из таблицы, выполнить `promtool check config /etc/prometheus/dao-prometheus.yml`, JSON-проверку, `systemctl daemon-reload` для изменённых drop-ins и перезапустить только изменённые сервисы. Затем `validate.sh` и визуальная проверка. Не запускать fresh-only `install.sh` для обновления.
- Пакеты: проверить release/security notes и точную версию из подписанного репозитория. Перед обновлением остановить Grafana и сохранить её SQLite, секреты и конфигурацию в **зашифрованную резервную копию вне VPS**. Не копировать живую SQLite простым `cp`. Копия должна быть доступна владельцу; в Git её не помещать. Снять hold только с обновляемого пакета, установить точную версию, вернуть hold, записать версию и SHA конфигурации, запустить и проверить. Hold требует регулярной ручной проверки security-обновлений.
- Откат конфигурации: вернуть прежние файлы/drop-ins и перезапустить соответствующие сервисы. Откат Grafana после миграции БД требует **совместимого старого пакета и соответствующей копии БД/secret-key**, одного downgrade пакета недостаточно. Хранить проверенные старые `.deb` в закрытом хранилище выпусков, если нужен гарантированный быстрый откат: APT не обещает бессрочную доступность версии.
- Метрики короткого срока хранения можно не резервировать: после аварии появится разрыв истории. Конфигурации, пользователи Grafana и секреты — отдельный предмет восстановления; резервная копия мониторинга не сохраняет заявки API.

## Остановить или удалить

Быстро освободить ресурсы, сохранив настройки и историю:

```sh
sudo systemctl disable --now grafana-server prometheus prometheus-node-exporter
sudo systemctl mask grafana-server prometheus prometheus-node-exporter
```

После проверки, что это именно установленный этим комплектом monitoring, удалить только эти пакеты:

```sh
sudo apt-mark unhold grafana prometheus prometheus-node-exporter
sudo apt-get remove grafana prometheus prometheus-node-exporter
```

Не применять `purge`, `autoremove` или удаление `/var/lib` без отдельного решения владельца. Конфигурации, секреты, БД, drop-ins, маски и запись версий сохраняются для восстановления; существующие nginx/API не затрагиваются. Если Grafana больше не нужна, отдельно удалить принадлежащие этому комплекту `/etc/apt/sources.list.d/dao-grafana.list` и `/etc/apt/keyrings/dao-grafana.asc`. Для восстановления использовать сохранённые версии/данные и проверенные private-конфиги, затем снять маски и включить три сервиса; fresh-only установщик преднамеренно откажется перезаписывать оставшееся состояние.

## Статус проверки комплекта

Локально проверяются shell-синтаксис, JSON/INI и согласованность файлов. На macOS не выполняются `apt`, systemd и Linux collectors; `promtool` и Grafana здесь не установлены. До получения ОС/SSH не заявлять, что комплект установлен или прошёл runtime-проверку. Поддерживаемые пути бинарников соответствуют пакетам [Debian node_exporter](https://packages.debian.org/bookworm/amd64/prometheus-node-exporter/filelist); collectors и метрики описаны в [официальном node_exporter](https://github.com/prometheus/node_exporter#collectors) и [руководстве Prometheus](https://prometheus.io/docs/guides/node-exporter/).
