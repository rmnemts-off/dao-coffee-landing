# Проверка VPS — 25.10.2026

Инфраструктура установлена и проверена после обновления ОС и реальной перезагрузки VPS; смена boot ID подтверждена. Это статус серверной подготовки, не публикация лендинга или проверка доставки заявок в Bitrix24.

Обновление пакетов завершено, `dpkg --audit` не обнаружил проблем. Несовместимость старого демона fwupd с обновлённой библиотекой устранена установкой официального пакета `fwupd 2.0.20`; после перезагрузки ошибок диагностики APT и failed systemd units не обнаружено.

## Что проверено

- `nginx`, `grafana-server`, `prometheus`, `prometheus-node-exporter` активны и включены в автозагрузку; после перезагрузки у каждого `NRestarts=0`.
- `monitoring/validate.sh` проходит: службы работают, мониторинг слушает только loopback, БД Grafana готова, target node доступен, анонимный API запрещён. Фактические флаги Prometheus admin API и lifecycle имеют значение `false`; совместимость boolean-флагов пакета Ubuntu исправлена в `fb10a81`.
- Nginx обслуживает только [holding-конфигурацию](nginx/dao-holding.conf): GET `/` и `/api/leads` дают `503`, `/.env`, `/grafana/`, `/metrics` — `404`. Произвольный Host также получает `503`.
- С внешнего Mac порт 80 доступен; подключения к 3000, 9090, 9100 и 4322 недоступны.
- Авторизованный вход через API Grafana работает. Provisioned-дашборд «DAO · Сервер» найден; все 13 различных PromQL-запросов дашборда через Grafana datasource proxy вернули непустые результаты с конечными числовыми значениями.

**Визуальная проверка в браузере не выполнена:** инструмент управления браузером был недоступен. Проверка API и данных не заменяет проверку отображения панелей. Вход для оператора — через SSH-туннель на `http://localhost:3000/`, как описано в [инструкции мониторинга](monitoring/README.md#проверка-и-вход); реквизиты хранятся отдельно от репозитория.

## Синхронизация исходников

При подготовке версии для VPS в `backend/telegram` включён согласованный фронтенд из `main` (`01492ef`, PR №1). Сохранены Bitrix-транспорт и контракт форм; объединены проверки frontend/backend. После интеграции `npm run check` и все 39 mock/DOM/HTTP-тестов прошли.

Код для проверки переносится из фиксированного коммита в `/srv/dao-coffee/releases/<FULLSHA>`, ссылка `staged` указывает на проверенный каталог. Архив и каждый файл проверяются по SHA256. В релиз входят только отслеживаемые Git-файлы; локальные `.env`, доступы, `.git` и `node_modules` не переносятся. Идентификатор коммита, исходной ветки, контрольная сумма архива и манифест записываются в `.release-meta/` внутри каталога релиза. Размещение `staged` не включает API, публичный frontend или TLS.

## Обновления мониторинга

Официальный Grafana APT возвращал `403` при обращении с VPS. Для установки использовалась временная loopback-переадресация через SSH и Mac с сохранением проверки подписи репозитория. После установки relay и временная настройка APT-прокси удалены. Запись официального Grafana-репозитория сейчас закомментирована; исходная запись сохранена на сервере. Пакеты Grafana, Prometheus и node_exporter поставлены на hold для ручного обновления.

Для следующего обновления нужен доступный проверенный официальный источник либо временный SSH-relay с проверкой подписи. Затем проверить точные версии и выполнить процедуру [ручного обновления](monitoring/README.md#обновление-и-откат). **Не запускать fresh-only установщик повторно** поверх действующей установки. Наличие hold требует отдельной проверки security-обновлений.

## Что остаётся до production

API unit установлен, но выключен и неактивен; пользователь `dao-coffee` создан. Environment-файл, origin и параметры Bitrix24 ещё не настроены. Production-релиз не активирован: ссылка `current` отсутствует, фронтенд не опубликован, DNS не менялся, реальные тестовые карточки CRM не создавались.

Остаются настройка Bitrix24 и согласованная проверка доставки с учётом роботов CRM, подтверждение домена и HTTPS, публикация проверенного релиза, визуальная приёмка Grafana, нагрузочная проверка всей связки и зашифрованная резервная копия вне VPS с проверкой восстановления.
