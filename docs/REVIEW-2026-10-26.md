## Исправленный критичный риск

На VPS оставался разрешён вход root по паролю, ранее раскрытому в переписке.
Установлен `backend/deploy/ssh/00-dao-key-only.conf` в
`/etc/ssh/sshd_config.d/00-dao-key-only.conf`. Теперь SSH допускает только ключи,
парольная и keyboard-interactive аутентификация отключены.

Перед применением проверено отдельное соединение по ключу; настроен временный
автоматический откат, выполнены `sshd -t` и reload SSH. После reload новое
соединение по ключу успешно установлено, откат отменён. Сайт и API не
перезапускались. VPN, DNS, ключи, пароль консоли провайдера и CRM не менялись.

Для нового сервера сначала установить и проверить SSH-ключ в отдельном
соединении, сохранить доступную сессию и подготовить откат. Затем установить
конфигурацию, проверить `sshd -t` и эффективные параметры через `sshd -T`,
перезагрузить конфигурацию и ещё раз проверить новый вход. Нельзя применять
этот файл до проверки ключа: парольный SSH-вход после этого не работает.

## Действующий сервер и Bitrix

- API, Nginx и PostgreSQL работают; `/readyz` отвечает `200` локально.
  PostgreSQL доступен только через Unix socket. API и мониторинг слушают
  loopback. Снаружи не открыты порты базы, Grafana и Prometheus.
- Служебные HTTP-пути, `.env`, `.git`, серверный код и журнал заявок возвращают
  `404`; `/api/leads` по GET — `405`. Неверные POST-запросы возвращают безопасный
  JSON без внутренней диагностики и секретов.
- Runtime-роль PostgreSQL не имеет CREATE в схеме, DELETE и TRUNCATE заявок.
  Секреты и резервные копии имеют закрытые файловые права.
- Bitrix проверен только чтением. Настроенные тип сущности (сделка), категория,
  начальная стадия и источник существуют. В PostgreSQL — 2 доставленные заявки;
  обе карточки найдены в Bitrix с совпадающими ID. Записей или изменений в CRM
  во время этого ревью не выполнялось.
- Боевой процесс использует PostgreSQL. SQLite остаётся для локальных mock и
  закрытого исторического архива; автоматического переключения на SQLite нет.
- HTTPS-проверка с внешнего подключения прошла с проверкой цепочки сертификата
  и IP `109.70.28.63`. Таймеры продления сертификатов и резервного копирования

  A-адресом; `www` — CNAME на основной домен, AAAA отсутствует. Сертификат

## Оставшиеся эксплуатационные ограничения

Успешная проверка с другой сети не закрывает эту проблему. В Руцентре открыто
обращение №2026102610002837; сетевые эксперименты с MSS отменены. Новые
сертификаты или изменение фронтенда без диагноза эту проблему не доказывают и
не устраняют.

Ежедневные резервные копии пока хранятся на VPS; первоначальные копии также
сохранены на Mac. Постоянное независимое внешнее хранилище резервных копий не
настроено. При неопределённом результате CRM заявка остаётся в журнале и требует
сверки; автоматическая повторная запись в CRM намеренно запрещена.

Визуал, тексты, контракт форм, схема бизнес-процесса и маршрутизация заявок не
изменялись. Результат ревью относится к указанному релизу и проверкам выше.
