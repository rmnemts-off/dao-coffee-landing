# Стартовый промпт — бэкенд

Ты отвечаешь за обработку заявок DAO COFFEE GROUP и интеграцию с Telegram в репозитории https://github.com/rmnemts-off/dao-coffee-landing.

Сначала прочитай `AGENTS.md`, `README.md`, `docs/FORM_CONTRACT.md`, затем текущий `site/scripts/forms.js`. Проверь ветку и локальные изменения. Работай в `backend/telegram`, начиная с текущего `main`, в отдельном клоне или worktree. Фронтенд параллельно работает над визуалом в другой ветке.

Исходная форма уже умеет открываться по контексту бренда, хранить независимые черновики в памяти, нормализовать +7, выбирать несколько интересов и валидировать поля. Сетевой отправки сейчас нет. Твоя задача — реализовать рабочий `POST /api/leads` по версии 1 контракта и отправку заявки в Telegram через сервер, затем подключить транспорт и состояния в `forms.js`.

Уточни у Романа серверную платформу, Telegram-бота, точный chat ID/получателя и разрешённый тестовый чат. Не угадывай адресата по публичным контактам. Пока доступов нет, продолжай независимую работу: обработчик, адаптер Telegram, конфигурация через окружение, понятные примеры переменных и локальные тесты с mock. Не заявляй, что реальная доставка проверена. Для текущего статического сайта выбирай минимальное решение под подтверждённый хостинг; не переноси весь фронтенд на новый стек ради одного endpoint.

Реализуй серверную валидацию, ограничение размера/частоты запросов, экранирование данных, timeout и обработку ошибок Telegram, защиту от повторной отправки. Секреты только на сервере и вне Git. Не логируй полную заявку и не раскрывай upstream-ответы с чувствительными данными. Не добавляй CRM, Битрикс, конфигуратор, оплату, базу заявок и другие интеграции без нового поручения.

Подключи общую модальную, брендовые и нижнюю формы. Сохрани все существующие контексты, маску, черновики, интересы, доступность и поведение dialog. Показывай успех только после подтверждённой доставки; при ошибке сохраняй заполнение. Введи понятные состояния отправки и блокировку повторного нажатия. Сверься с FORM_CONTRACT и не меняй схему односторонне.

Твои файлы: серверная папка и её конфигурация, `site/scripts/forms.js`, при необходимости отдельный транспорт. Визуал, фотографии, тексты брендов, `design.css` и анимации не переделывай. Если нужно подключение скрипта в HTML, внеси только эту минимальную правку и явно отметь её в PR для фронтенда. Не работай в его ветке и не меняй общий рабочий каталог коллеги.

Добавь содержательные тесты: успешная и неуспешная доставка, невалидные данные, направления, согласие, timeout и двойная отправка. Запусти `npm run check` и свои тесты, проверь состояние форм в браузере. Реальную пробную отправку выполняй только с согласованным тестовым адресатом. Перед production нужны подтверждённые документы для обработки персональных данных; не сочиняй их.

По завершении: укажи реализованное, результаты тестов и оставшиеся настройки; приложи понятную инструкцию запуска/размещения и пустой `.env.example`. Сделай коммит и push только в `backend/telegram`, создай PR в `main`. Не сливай PR и не публикуй/не переключай домен без отдельной команды Романа.
